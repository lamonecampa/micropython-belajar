Pengujian sistem embedded

Perangkat yang berhasil menjalankan demo belum tentu siap digunakan. Pengujian perlu memisahkan logika perangkat lunak, interaksi hardware, dan perilaku sistem dalam kondisi buruk.

MICROPYTHON BELAJAR · 6–10 MENIT BACA

Lapisan pengujian

  • Unit test: fungsi konversi, validasi, state machine, dan logika murni.
  • Integration test: komunikasi antar modul dan periferal.
  • Hardware test: sensor, tegangan, timing, dan aktuator.
  • System test: operasi jangka panjang dan skenario kegagalan.

Uji logika di komputer

Pisahkan fungsi yang tidak bergantung pada machine agar dapat diuji dengan Python desktop. Gunakan hardware abstraction atau mock object untuk driver.

def status_suhu(nilai):
    if nilai < 20: return "dingin"
    if nilai > 30: return "panas"
    return "normal"

assert status_suhu(10) == "dingin"
assert status_suhu(25) == "normal"
assert status_suhu(35) == "panas"

Uji fault injection

Simulasikan sensor gagal, payload rusak, broker tidak tersedia, filesystem penuh, dan suplai daya tidak stabil. Tentukan hasil yang diharapkan sebelum menguji.

Uji ketahanan

Jalankan perangkat dalam periode panjang, catat restart, memory, kehilangan pesan, dan drift pengukuran. Gunakan watchdog hanya dengan mekanisme pemulihan yang benar.

Format laporan pengujian

Catat versi software, board, kondisi lingkungan, langkah, hasil yang diharapkan, hasil aktual, bukti, dan status lulus/gagal. Pengujian yang dapat diulang lebih berharga daripada video demo yang tidak menjelaskan apa pun.
